# 投稿ストック管理

**目的: 残り本数を一目で分かるようにして、切れる前に次の制作に入る。**

Week単位(11〜12本まとめ書き)だと、データが台本に反映されるのが最短でも7日後になる。
維持率が出るまで最長2日かかることを踏まえ、**3日サイクル(2本/日 = 6本ずつ)**に切り替える。

## 補充ルール

| ストック残 | やること |
|---|---|
| 3本以上 | 何もしない |
| **2本** | **次の6本の制作に入る**(この時点で着手すれば切れない) |
| 1本以下 | 手遅れ。当日制作になる |

**「2本」を発注点にしている理由:** 2本 = 1日分。制作は台本〜レンダリングで数時間かかるため、
1日の余裕があれば通常のペースで間に合う。

### 8/23 追加: 冒頭カットの帯タグ・延長機能

冒頭テロップに「おすすめAIプロンプト」のような小さいラベルを乗せたい/冒頭カットをもう少し長く見せたい、という要望に対応する2つの台本フィールドを追加(`RankingVideo.tsx` / `build_props_generic.mjs`)。

- `"kicker": "テキスト"` — hookシーンの主テロップの上に小さい帯タグを1つ出す。**冒頭カット(最初のシーン)だけに付けるのが基本**(2カット目以降のフックには付けない)。
- `"extraPad": 1` — そのシーンの尺をナレーション終了後+N秒だけ延長する(テロップを長く見せたい時用)。

w6d/w6e/w6fの冒頭カットに両方とも適用済み。今後「おすすめAIプロンプト」を入れたい台本には同じ2フィールドを1シーン目に足すだけでよい。

### 8/23 再確認: テロップの孤立記号バグの直し方

`「`や`」`、読点`、`が行頭/行末で1文字だけ浮く問題は、**手動`\n`を1つ足すだけでは直らないことがある**(w6f_shiryouで再現)。原因は、鍵括弧で囲んだ強調フレーズ+前後の文字が980px幅にギリギリ収まらず、`\n`で区切った内側でさらに折り返しが起きるため。
**最も安定する直し方は「該当フレーズを短くする」**(w4p/w6dで有効だった方法と同じ)。`\n`はあくまで文の区切り位置を変えるためのもので、幅が原因の孤立には効かない。QAフレームで孤立を見つけたら、まずフレーズ短縮を試すこと。

## 制作の手順

台本さえ書ければ、あとは1コマンドで終わる。

```bash
cd shorts
tools/make_video.sh scripts/<名前>.json
```

これで 音声合成 → props生成 → レンダリング → QAフレーム抽出 まで通る。
テロップだけ直したときは `--skip-voice` を付けると音声を作り直さない。

**自動化していない工程(人がやる):**

1. **台本を書く** — 順位の根拠、テロップの言い回し、背景の割り当て、実測値を入れない判断
2. **QAフレームの目視** — テロップのはみ出し・折り返しの崩れは機械では検出できない
3. **読みの確認** — `⚠` が出た語は実際に音声を聞く(テキストからの推測で判断しない)
4. **`out/`に完成mp4を置くこと** — クラウド側でレンダリングしたファイルをMacに持ってくる作業のみ人が行う。
   置いたあとの予約投稿は自動(下記)

## 自動予約投稿(2026/8/21構築)

`out/`に動画を置くだけで、次の空き枠(7:00/21:00を交互に)へ自動で予約投稿される。

**セットアップ(初回のみ、Macで実施):**

```bash
cd ~/takahiro/shorts
cat tools/last_scheduled.txt   # 直近に実際に予約した日時になっているか確認・修正
bash tools/install_auto_upload.sh          # 15分おきにチェック
bash tools/install_auto_upload.sh 600      # 間隔を変える場合(秒数)
bash tools/install_auto_upload.sh --uninstall
```

**使い方: `tools/post_queue.txt`に投稿順で台本名を書いておくだけ。**
先頭の台本の`out/<名前>.mp4`が置かれたら、次に起動したタイミングで自動予約し、
その行をキューから消して次に進む。

- 動作確認(実際には予約しない): `python3 tools/auto_upload_watch.py --dry-run`
- 手動で1回だけ動かす: `launchctl start com.shigotoai.autoupload`
- ログ: `.auto_upload.log`(毎回追記。git管理外)

**⚠ 予約できたときだけ通知が来る。** 動画がまだ届いていない待機中は通知しない。
**⚠ この工程だけ自動化した。** 台本を書く・QAの目視・読みの確認は判断が要るため
引き続き人がやる(上記の表のとおり)。
**⚠ 認証情報はMacのローカルにしか置いていない**(意図的な設計)。
このため、この自動化もMac側でしか動かない。クラウド側のセッションが
mp4を作ったら、`out/`に転送するところまでは今まで通り人が行う。

判断が要るため自動化していない(下表のとおり)。

### ⚠ APIクォータ: 1日6本まで

`videos.insert` は1本1,600ユニット、1日の枠は10,000。**6本で9,600に達する。**
失敗して上げ直すと枠を食うので、必ず `--dry-run` を通してから実行すること。
