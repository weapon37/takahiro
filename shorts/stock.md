# 投稿ストック管理

**目的: 残り本数を一目で分かるようにして、切れる前に次の制作に入る。**

Week単位(11〜12本まとめ書き)だと、データが台本に反映されるのが最短でも7日後になる。
維持率が出るまで最長2日かかることを踏まえ、**3日サイクル(2本/日 = 6本ずつ)**に切り替える。

## 補充ルール

| ストック残 | やること |
|---|---|
| 3本以上 | 何もしない |
| **2本** | **次の6本の制作に入る**(この時点で着手すれば切れない) |
| 1本以下 | 手遅れ。当日制作になる |

**「2本」を発注点にしている理由:** 2本 = 1日分。制作は台本〜レンダリングで数時間かかるため、
1日の余裕があれば通常のペースで間に合う。

## 制作の手順

台本さえ書ければ、あとは1コマンドで終わる。

```bash
cd shorts
tools/make_video.sh scripts/<名前>.json
```

これで 音声合成 → props生成 → レンダリング → QAフレーム抽出 まで通る。
テロップだけ直したときは `--skip-voice` を付けると音声を作り直さない。

**自動化していない工程(人がやる):**

1. **台本を書く** — 順位の根拠、テロップの言い回し、背景の割り当て、実測値を入れない判断
2. **QAフレームの目視** — テロップのはみ出し・折り返しの崩れは機械では検出できない
3. **読みの確認** — `⚠` が出た語は実際に音声を聞く(テキストからの推測で判断しない)
4. **YouTubeへのアップロード** — 自動化されていない(下記)

### 残数チェックから制作までの流れ

```bash
cd shorts
python3 tools/youtube_stock.py            # 残数を見る。2本以下なら終了コード9
tools/make_video.sh scripts/<名前>.json   # 制作(音声→書き出し→QAフレーム)
# QAフレームを目視確認
python3 tools/youtube_upload.py scripts/<名前>.json --at "2026-08-21 07:00" --dry-run
python3 tools/youtube_upload.py scripts/<名前>.json --at "2026-08-21 07:00"
```

### 毎日の残数チェック(launchd)

Macに登録すると、**毎朝9時に残数を確認し、2本以下なら通知**が出る。
足りているときは通知しない(毎日鳴ると無視するようになるため)。
トークン失効やAPI障害で失敗したときは、黙って止まらないよう必ず通知する。

```bash
cd ~/takahiro/shorts
bash tools/install_stock_check.sh          # 毎朝9:00で登録
bash tools/install_stock_check.sh 21 30    # 時刻を変える場合
bash tools/install_stock_check.sh --uninstall
```

- 手動実行: `bash tools/stock_check.sh`
- ログ: `.stock_check.log`(毎回追記。git管理外)
- ⚠ Macがスリープ・電源オフの時刻は実行されず、次に起きたときに実行される
- ⚠ 初回は通知の許可が必要なことがある(システム設定 → 通知 → スクリプトエディタ)

**これで自動になるのは「残数の見張り」だけ。** 台本を書く工程とQAの目視は
判断が要るため自動化していない(下表のとおり)。

### ⚠ APIクォータ: 1日6本まで

`videos.insert` は1本1,600ユニット、1日の枠は10,000。**6本で9,600に達する。**
失敗して上げ直すと枠を食うので、必ず `--dry-run` を通してから実行すること。
