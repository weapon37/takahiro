# 投稿ストック管理

**目的: 残り本数を一目で分かるようにして、切れる前に次の制作に入る。**

Week単位(11〜12本まとめ書き)だと、データが台本に反映されるのが最短でも7日後になる。
維持率が出るまで最長2日かかることを踏まえ、**3日サイクル(2本/日 = 6本ずつ)**に切り替える。

## 補充ルール

| ストック残 | やること |
|---|---|
| 3本以上 | 何もしない |
| **2本** | **次の6本の制作に入る**(この時点で着手すれば切れない) |
| 1本以下 | 手遅れ。当日制作になる |

**「2本」を発注点にしている理由:** 2本 = 1日分。制作は台本〜レンダリングで数時間かかるため、
1日の余裕があれば通常のペースで間に合う。

## 制作の手順

台本さえ書ければ、あとは1コマンドで終わる。

```bash
cd shorts
tools/make_video.sh scripts/<名前>.json
```

これで 音声合成 → props生成 → レンダリング → QAフレーム抽出 まで通る。
テロップだけ直したときは `--skip-voice` を付けると音声を作り直さない。

**自動化していない工程(人がやる):**

1. **台本を書く** — 順位の根拠、テロップの言い回し、背景の割り当て、実測値を入れない判断
2. **QAフレームの目視** — テロップのはみ出し・折り返しの崩れは機械では検出できない
3. **読みの確認** — `⚠` が出た語は実際に音声を聞く(テキストからの推測で判断しない)
4. **YouTubeへのアップロード** — 自動化されていない(下記)

## 完全自動化に足りないもの

現状「ストックが2本になったら自動で作る」までは届かない。壁は2つ。

| 足りないもの | 必要な作業 |
|---|---|
| **ストック残数の自動取得** | YouTube Data API v3(読み取り)。OAuth設定が要る |
| **アップロードの自動化** | YouTube Data API v3(`videos.insert`)+ OAuth。リポジトリ内に実装は存在しない |

> 確認済み: 別ブランチ `social-media-automation-system-bn9xq5` にある自動投稿は
> **Threads専用**で、コードに「その他のプラットフォームへの自動投稿は未対応」と明記されている。
> YouTubeの投稿自動化はこのリポジトリのどこにもない。

APIを繋げば、①残数の自動チェック → ②不足していれば通知 → ③制作 → ④予約投稿まで
一本化できる。ただしOAuthの同意画面・リフレッシュトークン管理・APIクォータの検討が必要で、
これは独立した作業になる。**8/18の判定後、継続すると決まってから着手するのが妥当。**
