# YouTube API の設定手順(1回だけ)

投稿と残数確認を自動化するための準備。**手元のMacで作業すること**
(ブラウザでの承認が必要なため、リモート環境ではできない)。

所要時間は10〜15分。以降は再認証不要。

---

## 手順1: プロジェクトを作る

1. https://console.cloud.google.com/ を開く
2. 上部のプロジェクト選択 → **新しいプロジェクト**
3. 名前は何でもよい(例: `shorts-uploader`)→ 作成

## 手順2: YouTube Data API v3 を有効にする

1. 左メニュー **APIとサービス** → **ライブラリ**
2. `YouTube Data API v3` を検索して開く
3. **有効にする**

## 手順3: OAuthクライアントを作る

> ⚠ 2026年8月時点のConsoleでは、旧「OAuth同意画面」が
> **「Google Auth Platform」**という画面に置き換わっている。左メニューの対応は下記。
>
> | 旧UI | 新UI(左メニュー) |
> |---|---|
> | OAuth同意画面のアプリ情報 | **ブランディング** |
> | User Type・テストユーザー | **対象** |
> | スコープ | **データアクセス** |
> | 認証情報 → OAuthクライアントID | **クライアント** |

### 3-1. 「対象」でテストユーザーを登録する(最重要)

1. 左メニュー **対象** を開く
2. **User Type が「外部」**になっていることを確認
3. 公開ステータスは **「テスト中」のままでよい**(本番公開の申請は不要)
4. **テストユーザーに、使う可能性のあるGoogleアカウントを全部追加する**(100件まで登録可)

⚠ **ここを忘れると、承認時に「アクセスをブロック: ○○ は Google の審査プロセスを
完了していません / エラー 403: access_denied」で止まる。**

> **実際にハマった例(2026/8/15):** 1つ目のアカウントだけ登録した状態で、
> 別アカウント(チャンネルの実際の所有者)で承認しようとして弾かれた。
> **アカウントごとに登録が必要。** 複数アカウントを使い分けているなら、
> 最初にまとめて登録しておくと詰まらない。

### 3-2. 「ブランディング」を埋める

アプリ名・ユーザーサポートメール・デベロッパーの連絡先を入力する(自分のメールでよい)。
すでに入力済みなら飛ばしてよい。

### 3-3. 「データアクセス」は触らなくてよい

スコープはコード側(`youtube_api.py` の `SCOPES`)で指定しているため、
ここでの追加は不要。テストユーザーとして自分で使う限りこれで通る。

### 3-4. 「クライアント」でクライアントIDを作る

1. 左メニュー **クライアント** → **クライアントを作成**
2. アプリケーションの種類は **デスクトップアプリ** を選ぶ
   - ⚠ 「ウェブアプリケーション」だとリダイレクトURIの設定が別途必要になる
3. 作成 → **JSONをダウンロード**
4. ダウンロードしたファイルを **`shorts/client_secret.json`** という名前で置く

> `client_secret.json` と `.youtube_token.json` は `.gitignore` 済み。
> **絶対にコミットしないこと。**

## 手順4: 概要欄のフッターを直す

`shorts/tools/description_footer.txt` の `【チャンネルID】` を実際のハンドルに置き換える。
置き換えないとアップロード時にエラーで止まる(意図的なガード)。

## 手順5: 認証する

```bash
cd shorts
python3 tools/youtube_auth.py
```

ブラウザが開くので承認する。「このアプリは確認されていません」と出たら
**詳細 → (アプリ名)に移動** で進む(自分が作ったアプリなので問題ない)。

### ⚠ チャンネルの選び方(ブランドアカウントの罠)

「仕事が消えるAI帳」のようなチャンネルが**ブランドアカウント**として作られている場合、
承認の途中に**アカウント/チャンネルの選択画面**が出る。
ここで個人チャンネルを選ぶと、**別チャンネルのデータを操作することになる。**

> **実際にハマった例(2026/8/15):** 個人チャンネルで認証してしまい、
> 予約8本あるはずが「予約済み: 0本」と表示された。`--dump` で中身を見たら
> マラソンや講演など2012〜2025年の個人動画ばかりで発覚した。

このため認証の最後に**認証したチャンネル名とIDを必ず表示する**ようにしてある。

```
==============================================
認証したチャンネル: 【仕事が消えるAI帳】
チャンネルID: UC0vOe3h9o97b6Wv7oeDW-Og
==============================================
```

**ここが目的のチャンネルでなければ、表示される手順でやり直すこと**
(トークン削除 → https://myaccount.google.com/connections で連携解除 → 再認証)。

成功すると `.youtube_token.json` が作られる。

## 手順6: 動作確認

```bash
python3 tools/youtube_stock.py
```

予約済みの動画が一覧表示されれば成功。

## 使い方

### 残り本数を見る

```bash
python3 tools/youtube_stock.py
```

発注点(2本)以下だと終了コード9を返すので、シェルで分岐できる。

```bash
python3 tools/youtube_stock.py --quiet || echo "補充が必要"
```

### 投稿する

**必ず `--dry-run` で確認してから本番を実行すること。**

```bash
# 1) 送信内容を確認
python3 tools/youtube_upload.py scripts/w5a_example.json --at "2026-08-21 07:00" --dry-run

# 2) 問題なければ実行
python3 tools/youtube_upload.py scripts/w5a_example.json --at "2026-08-21 07:00"
```

`--at` を省略すると下書き(非公開)として上がる。日時は**日本時間**で指定する。

### 制作から投稿までの流れ

```bash
cd shorts
tools/make_video.sh scripts/w5a_example.json          # 音声→props→書き出し→QAフレーム
# QAフレームを目視で確認する
python3 tools/youtube_upload.py scripts/w5a_example.json --at "2026-08-21 07:00" --dry-run
python3 tools/youtube_upload.py scripts/w5a_example.json --at "2026-08-21 07:00"
```

## ⚠ 制約と注意

### APIクォータ: 1日6本まで

| 操作 | 消費ユニット |
|---|---|
| 動画の投稿(`videos.insert`) | **1,600** |
| 残数の確認(`youtube_stock.py`) | 3〜5 |
| 1日の既定枠 | **10,000** |

**6本投稿すると9,600ユニットで、ほぼ上限に達する。** 失敗して上げ直すと枠を食うため、
必ず `--dry-run` で内容を確認してから実行すること。枠は太平洋時間の0時にリセットされる。

6本バッチを1日で全部上げる運用なら、この上限は覚えておく必要がある。
足りなくなった場合はConsoleから増枠申請できるが、審査がある。

### 自動化していないこと

| 項目 | 理由 |
|---|---|
| **「AIの使用」の開示設定** | APIでの設定を確認できていないため、投稿後にStudioで設定する。現行運用はニュース回が「いいえ」、他は「はい」 |
| **固定コメント** | APIで投稿はできるが、現状は手作業のまま |
| **サムネイル** | ショートは自動生成のため設定していない |
| **台本を書く工程** | 判断が必要なため自動化しない |
| **QAフレームの目視確認** | テロップのはみ出しは機械では検出できない |

### トラブル時

| 症状 | 対処 |
|---|---|
| 「アクセスをブロック / エラー403: access_denied」 | **そのアカウント**がテストユーザーに未登録。手順3-1で追加する(アカウントごとに必要) |
| 予約が0本と出る / 身に覚えのない動画が並ぶ | 別チャンネルで認証している。`--dump`で中身を確認し、手順5のやり直し手順を実行 |
| `refresh_token が返ってきませんでした` | Googleアカウントの「サードパーティ アプリとの連携」から該当アプリを削除して再実行 |
| `アクセストークンの取得に失敗(400)` | トークンが失効している。`youtube_auth.py` をやり直す |
| `quotaExceeded` | その日の枠を使い切った。翌日(太平洋時間0時リセット)まで待つ |
